## 순서
1. 사용자가 ChangeRequest_create(source, body, entryStep) 로 접수한다 (열림)
2. AI 가 Context_forChangeRequest 로 영향 항목을 받고 setState(반영 중)
3. 진입 단계부터 다시 라운드를 돌며 체크포인트를 찍는다. Journey 는 이 구간의 온 이유를 CR 로 보인다
4. 끝나면 setState(완료/거부), 닫힌 체크포인트가 기록된다. 열린 CR 이 있으면 RELEASE 할 수 없다

## 데이터 흐름
CR 본문·진입 단계 → 단계 입력 → 새 체크포인트들 → CR 상태
