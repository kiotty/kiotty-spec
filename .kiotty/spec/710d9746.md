## 진술
한 프로젝트의 기록은 한 사람이 관리한다. 그 사람은 기록을 코드와 함께 git 에 커밋해 보관하고, 다른 컴퓨터나 다른 브랜치로 옮겨도 커밋된 기록으로 같은 상태를 되살리며, 필요할 때 사람이 읽는 문서(요구사항서, 설계서, 테스트 계획서, 개발 계획서, 추적 보고서)로 뽑아 본다.

## 근거 시나리오
1. 사용자가 코드를 커밋할 때 기록도 텍스트 파일로 함께 커밋된다.
2. 다른 컴퓨터에서 저장소를 받거나 브랜치를 바꾸면, 커밋된 파일로 기록이 그 시점 상태로 다시 만들어진다.
3. 검토할 때는 종류별 문서로 뽑아 본다. 이미 쓴 문서를 항목으로 가져올 수도 있다.
4. 여러 사람이 같은 기록을 브랜치로 나눠 고치고 합치는 것은 다루지 않는다 (261104_02_backlog.md).

## 인수 조건
- 전제 조건: 요구사항을 추가하고 커밋 / 행동: 다른 컴퓨터에서 저장소를 받아 현재 위치를 묻는다 / 기대 결과: 같은 요구사항과 같은 체크포인트 이력
- 전제 조건: 요구사항 여러 개 / 행동: 요구사항서를 뽑는다 / 기대 결과: 항목마다 ID·분류·제목·연결·본문이 있는 문서
