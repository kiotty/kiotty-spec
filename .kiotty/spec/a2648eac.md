## 순서
1. 테스트를 돌린 AI 가 Result_record(target, FAIL, log) 를 남긴다
2. Result_failedBegin 으로 마지막이 FAIL 인 대상을 얻는다
3. Result_suspectsBegin: 실패한 테스트 → 검증한다 → 설계 → 구현한다 → 소스 파일을 따라 원인 후보를 낸다
4. Link_scopeOf(후보): 설계 모듈 하나 안이고 그 모듈에 의존하는 모듈이 없으면 모듈 내, 아니면 모듈 간 + 영향 모듈 목록
5. 모듈 내는 AI 가 고치고, 모듈 간은 사용자에게 보고해 변경 요청으로 넘긴다

## 데이터 흐름
result 행 → 링크 그래프 탐색 → 항목·파일 ID 목록 → Scope
