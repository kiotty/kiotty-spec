## 개요
함수 9 개를 묶은 개념 단위. 함수별 계약은 하위 항목에 있고, 여기에는 묶음 공통의 타입과 규약을 둔다.

## 하위 함수
- UI-046 KiottySpec_Checkpoint_create
- UI-047 KiottySpec_Checkpoint_confirm
- UI-048 KiottySpec_Checkpoint_get
- UI-049 KiottySpec_Checkpoint_current
- UI-050 KiottySpec_Checkpoint_lastConfirmed
- UI-051 KiottySpec_Checkpoint_listBegin
- UI-052 KiottySpec_Checkpoint_changedItemsBegin
- UI-053 KiottySpec_Checkpoint_diff
- UI-054 KiottySpec_Checkpoint_confirmCheck

## 시그니처
```c
typedef enum KiottySpecCheckpointPurpose {
    KiottySpecCheckpointPurpose_None = 0,    /* 일반 라운드 */
    KiottySpecCheckpointPurpose_Release      /* 최초 개발 완료 (RELEASE) */
} KiottySpecCheckpointPurpose;

typedef struct KiottySpecCheckpoint {
    const char *id;                          /* "CP-0042" */
    int32_t step;                            /* 소속 개발 단계 1 ~ 10 */
    bool confirmed;                          /* 사용자 확정 여부 */
    KiottySpecCheckpointPurpose purpose;     /* 일반 / RELEASE */
    const char *note;                        /* 라운드 요약 한 줄 */
    int64_t createdAt;                       /* unix epoch */
} KiottySpecCheckpoint;
```

## 사전조건
- create 의 step 은 1 ~ 10
- confirm 의 actor 는 User (R-2)

## 사후조건
- create: 아직 묶이지 않은 쓰기를 CP-#### (4 자리, 이어지는 번호) 로 묶는다
- confirm: 단계별 확정 조건(R-3 ~ R-5)을 만족하면 확정. 이미 확정이면 그대로 Ok. 확정된 내용은 이후 바뀌지 않는다 (R-1)
- confirmCheck: 가능 여부와 이유 보고서, 기록은 바꾸지 않는다
- changedItemsBegin·diff: 두 시점 사이 추가·수정·삭제 (cpTo NULL 이면 현재까지)

## 에러 코드
- Ai 가 confirm: Permission
- 확정 조건 미충족: Precondition (보고서는 lastError)
- 아직 체크포인트로 묶이지 않은 쓰기(PENDING) 를 확정: InvalidArg
- 없는 CP: NotFound
- step 범위 밖: InvalidArg
- NULL 핸들·NULL 필수 인자는 InvalidArg, 상세는 KiottySpec_lastError

## 소유권
- create 의 *outId, get·current·lastConfirmed 의 *out, diff·confirmCheck 의 문자열은 호출자가 KiottySpec_free
- listBegin·changedItemsBegin 의 커서는 Cursor_end
