## 개요
함수 6 개를 묶은 개념 단위. 함수별 계약은 하위 항목에 있고, 여기에는 묶음 공통의 타입과 규약을 둔다.

## 하위 함수
- UI-094 KiottySpec_ChangeRequest_create
- UI-095 KiottySpec_ChangeRequest_get
- UI-096 KiottySpec_ChangeRequest_setState
- UI-097 KiottySpec_ChangeRequest_setEntryStep
- UI-098 KiottySpec_ChangeRequest_listBegin
- UI-099 KiottySpec_ChangeRequest_openCount

## 시그니처
```c
typedef enum KiottySpecChangeSource {
    KiottySpecChangeSource_Feedback = 1,     /* 사용자 피드백 */
    KiottySpecChangeSource_Issue             /* 이슈 (RELEASE 이후) */
} KiottySpecChangeSource;

typedef enum KiottySpecChangeState {
    KiottySpecChangeState_Open = 1,          /* 열림 */
    KiottySpecChangeState_InProgress,        /* 반영 중 */
    KiottySpecChangeState_Done,              /* 완료 */
    KiottySpecChangeState_Rejected           /* 거부 */
} KiottySpecChangeState;

typedef struct KiottySpecChangeRequest {
    const char *id;                          /* "CR-007" */
    KiottySpecChangeSource source;           /* 피드백 / 이슈 */
    const char *body;                        /* 요구 내용 */
    int32_t entryStep;                       /* 진입 단계 */
    KiottySpecChangeState state;             /* 상태 */
    const char *cpOpened;                    /* 접수 체크포인트 */
    const char *cpClosed;                    /* 완료 확정 체크포인트 (없으면 NULL) */
} KiottySpecChangeRequest;
```

## 사전조건
- entryStep 은 1 ~ 10
- Issue 출처는 RELEASE 이후에 쓰는 것이 정의서의 흐름 (구현은 검사하지 않음)

## 사후조건
- create: CR-### 발급, Open, 현재 체크포인트를 cpOpened 로
- setState(Done): 현재 체크포인트를 cpClosed 로
- setEntryStep 뒤 현재 위치 안내는 새 진입 단계부터

## 에러 코드
- 범위 밖 entryStep, 빈 body: InvalidArg
- 없는 CR: NotFound
- NULL 핸들·NULL 필수 인자는 InvalidArg, 상세는 KiottySpec_lastError

## 소유권
- create 의 *outId, get 의 *out 은 호출자가 KiottySpec_free
- 커서는 Cursor_end
