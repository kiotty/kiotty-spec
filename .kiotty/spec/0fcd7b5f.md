## 규칙
유닛 테스트는 tests/ 아래 모듈별 실행 파일로 두고 CTest 로 실행하며, 이름에 테스트 ID(UT-###)를 넣는다. 각 테스트는 새 임시 디렉토리에 프로젝트를 열어 서로 독립적이고, 끝나면 지운다. 시스템·E2E 테스트는 빌드된 ks 와 공개 C 헤더로만 구동한다.

## 이유
지금 저장소에는 kiotty-spec 자체의 테스트가 없다. 테스트 결과를 ks result 에 ID 로 기록하고, 테스트 사이의 DB 오염을 막기 위해서다.

## 검사 방법
ctest -N 의 테스트 이름과 DB 의 테스트 ID 대조, 테스트 코드에 고정 경로(.kiotty 를 저장소 루트에 여는 코드)가 없는지 grep
