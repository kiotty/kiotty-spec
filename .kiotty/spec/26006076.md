## 개요
함수 5 개를 묶은 개념 단위. 함수별 계약은 하위 항목에 있고, 여기에는 묶음 공통의 타입과 규약을 둔다.

## 하위 함수
- UI-055 KiottySpec_Checkpoint_position
- UI-056 KiottySpec_Checkpoint_journeyBegin
- UI-057 KiottySpec_Context_whereAmI
- UI-058 KiottySpec_Context_status
- UI-059 KiottySpec_Context_pending

## 시그니처
```c
typedef struct KiottySpecPosition {
    const char *checkpointId;                /* 가장 최근 체크포인트 (없으면 NULL) */
    int32_t step;                            /* 그 체크포인트의 단계 (없으면 0) */
    bool confirmed;                          /* 그 체크포인트가 확정되었는지 */
    bool released;                           /* RELEASE 이후인지 (유지보수 단계) */
    size_t pendingWrites;                    /* 아직 체크포인트에 묶이지 않은 쓰기 수 */
    int32_t nextStep;                        /* 다음에 진행할 단계 */
    const char *nextAction;                  /* 다음에 할 일 한 줄 */
} KiottySpecPosition;

typedef struct KiottySpecStepRun {
    int32_t step;                            /* 연속으로 머문 단계 */
    const char *firstCheckpointId;           /* 이 구간의 첫 체크포인트 */
    const char *lastCheckpointId;            /* 이 구간의 마지막 체크포인트 */
    const char *confirmedCheckpointId;       /* 이 구간에서 확정된 마지막 체크포인트 (없으면 NULL) */
    size_t checkpointCount;                  /* 이 구간의 라운드 수 */
    const char *lastNote;                    /* 마지막 라운드 요약 */
    const char *reason;                      /* 이 단계로 온 이유: "시작" / "다음 단계" / "CR-007 로 되돌아옴" / "RELEASE" */
} KiottySpecStepRun;
```

## 사전조건
- 없음. 체크포인트가 없어도 부를 수 있다

## 사후조건
- 위치·이력은 저장하지 않고 체크포인트와 변경 요청에서 계산한다 (R-12)
- 다음 할 일 순서: 미확정 체크포인트 확정 → 열린 변경 요청의 가장 앞 진입 단계 → 다음 단계. 묶이지 않은 쓰기가 있으면 체크포인트 안내가 붙는다
- journey 원소의 reason: "시작" / "다음 단계" / "CR-### 로 되돌아옴" / "RELEASE"
- whereAmI 는 maxBytes 안의 Markdown 한 페이지

## 에러 코드
- NULL 핸들·NULL 필수 인자는 InvalidArg, 상세는 KiottySpec_lastError

## 소유권
- position 의 *out, Markdown 문자열은 호출자가 KiottySpec_free
- journeyBegin 의 커서는 Cursor_end
