## 순서
1. 사용자가 Checkpoint_releaseCheck 로 조건을 본다: 열린 CR 없음, 모든 테스트 PASS 등 (R-10)
2. Checkpoint_release(User): Project 가 actor 와 조건을 검사하고 Step 10, 목적 RELEASE 체크포인트를 만들어 바로 확정한다
3. Checkpoint_prune(User, 기준 CP): 기준은 확정된 것이어야 하고, 기준 이전의 RELEASE 는 지울 수 없다
4. CheckpointStore.prune 이 기준 시점에 유효한 버전을 기준 CP 로 옮기고 그 이전 버전·결과·닫힌 CR·체크포인트를 지운다

## 데이터 흐름
버전 테이블들의 cp_seq < 기준 행 삭제, 기준 시점 뷰는 그대로
