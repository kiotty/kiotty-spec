## 진술
누구든 항목 하나에서 연결을 따라 위로는 "왜 있는가"(요구사항 쪽), 아래로는 "어디에 구현되고 무엇으로 검증되는가"(코드 쪽)를 볼 수 있고, 두 종류 사이의 추적표를 뽑을 수 있다.

## 근거 시나리오
사용자가 소스 파일 하나를 보고 이 코드가 어떤 요구사항 때문에 있는지 묻는다. 요구사항 하나가 어느 테스트로 검증되는지 확인한다. 리뷰 때는 요구사항 × 설계 추적표로 빈칸을 찾는다.

## 인수 조건
- 전제 조건: 요구사항 ← 설계 ← 유닛 테스트 / 행동: 유닛 테스트에서 위로 따라간다 / 기대 결과: 설계, 요구사항 (몇 단계까지 볼지 정할 수 있음)
- 전제 조건: 같은 연결 / 행동: 요구사항에서 아래로 따라간다 / 기대 결과: 설계, 유닛 테스트
- 전제 조건: 요구사항과 설계 여럿 / 행동: 요구사항 × 설계 추적표를 뽑는다 / 기대 결과: 연결된 칸이 표시된 표
- 전제 조건: 항목 하나 / 행동: 그 항목의 맥락을 묻는다 / 기대 결과: 항목 본문, 위·아래 연결 항목, 관련 결정 줄
