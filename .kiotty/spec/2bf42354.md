## 진술
AI 는 각 단계의 산출물(요구사항, 개발 규칙, 외부 인터페이스, 설계, 테스트, 마일스톤)을 항목으로 기록하고 "A 는 B 를 만족시킨다 / 검증한다 / 구현한다 / 포함한다 / 의존한다" 로 연결해, 어떤 항목이 왜 있고 어디서 쓰이는지가 끊기지 않게 한다.

## 근거 시나리오
1. Step 1 에서 요구사항을, Step 3 에서 외부 인터페이스를 기록하고 "인터페이스가 요구사항을 만족시킨다" 로 연결한다.
2. Step 4 ~ 6 에서 설계, 유닛 테스트, 마일스톤을 기록하고 연결한다.
3. 단계마다 왜 그렇게 정했고 무엇을 버렸는지를 결정 기록에 남긴다.
4. 나중에 누구든 요구사항 하나에서 그것을 구현·검증하는 것까지, 또는 코드 하나에서 그것이 있는 이유까지 따라간다.

## 인수 조건
- 전제 조건: 요구사항 ← 인터페이스 ← 설계 ← 유닛 테스트 로 연결되어 있다 / 행동: 유닛 테스트에서 위로 따라간다 / 기대 결과: 설계, 인터페이스, 요구사항이 차례로 보인다
- 전제 조건: 정의서에 없는 관계(예: 유닛 테스트가 요구사항을 검증) / 행동: 연결을 시도한다 / 기대 결과: 거부되고 허용되는 관계가 안내된다
