# 개발수칙 편차

개발수칙이나 참조 표준(MISRA C++:2023, CERT C++)을 지키지 못하는 곳과 그 이유, 위험을 줄이는 방법을 적는다. 편차를 없애면 이 문서에서도 지운다.

| 수칙 | 위치 | 편차 | 이유 | 완화책 |
| --- | --- | --- | --- | --- |
| MISRA C++:2023 21.6.1 (동적 메모리 금지) | `KiottySpec_createContext`, 풀 · 버퍼를 가진 클래스의 생성자 | 초기화 때 `std::vector`, `std::make_unique` 로 힙을 할당한다 | 용량을 설정값(`KiottySpecConfiguration`)으로 정해야 해서 컴파일 타임 배열로 둘 수 없다 (개발수칙 1.1) | 할당은 초기화 함수 안에서 한 번만 하고 그 뒤 크기를 바꾸지 않는다. 설정값은 `parseConfiguration` 이 범위를 검사하고, 곱한 용량은 `checkedMultiply` 로 넘침을 막는다. 할당 실패는 `-fno-exceptions` 로 process 를 끝낸다. `tools/lint.js` 가 초기화 함수 밖의 할당을 1.1 위반으로 센다 |
| 개발수칙 1.1 (힙 할당은 초기화 함수 안에서만) | `app/` (CLI) | 명령 실행 중에 `std::string`, `std::vector`, `std::map`, 표준 입출력으로 힙을 할당한다 | CLI 는 한 번 실행하고 끝나는 짧은 process 라 런타임 힙이 쌓이지 않고, 막으면 인자 · 출력 처리 비용이 지나치게 크다 | 라이브러리(`src/`)는 그대로 1.1 을 지킨다. CLI 는 C interface 만 거쳐 라이브러리를 쓴다. `tools/lint.js` 는 `app/` 의 1.1 을 세지 않는다 |
| 개발수칙 1.10 (Raw pointer 금지) | `include/`, C interface 어댑터(`src/kiotty_spec*.cpp`), CLI 에서 C 함수(`KiottySpec_*`, C 표준 라이브러리, Win32)를 부르거나 `KiottySpec*` 레코드를 다루는 줄 | C ABI 의 인자 · 레코드에 raw pointer 를 쓴다 | C 에는 길이와 포인터 말고 버퍼를 넘길 방법이 없다 | 포인터는 항상 길이와 함께 다니고(2.2), 어댑터가 `Span` 으로 바꿔 내부로 넘긴다. 경계 밖의 내부 코드(CLI 자체 포함)는 1.10 을 지킨다. `tools/lint.js` 는 이 줄들만 1.10 에서 뺀다 |
| 개발수칙 1.6 (컨테이너는 `core/` 의 고정 크기 컨테이너만) | `app/` (CLI) | `std::string`, `std::map`, `std::optional<std::string>` 등 표준 컨테이너를 쓴다 | 1.1 의 CLI 예외와 같은 이유. CLI 는 힙 할당을 허용하므로 표준 컨테이너를 막을 실익이 없다 | 라이브러리(`src/`)는 그대로 1.6 을 지킨다. `tools/lint.js` 는 `app/` 의 1.6 을 세지 않는다 |
| 개발수칙 3.4 (멤버 크기 내림차순, `static_assert(sizeof)` 로 패딩 고정) | `app/` (CLI) 의 struct | 크기 고정을 하지 않는다 | 표준 컨테이너를 담은 struct 는 표준 라이브러리 구현마다 크기가 달라 고정할 수 없다 | 라이브러리(`src/`)와 `include/` 는 그대로 3.4 를 지킨다. `tools/lint.js` 는 `app/` 의 3.4 를 세지 않는다 |
| 개발수칙 3.4 (멤버 크기 내림차순, `static_assert(sizeof)` 로 패딩 고정) | `Result` (`core/kiotty_result.h`), `ItemTables` (`data/repository/item/kiotty_item_tables.h`), `KiottySpecContext` (`src/kiotty_spec_adapter.h`) | 크기를 `static_assert(sizeof)` 로 고정하지 않는다 | `Result` 는 템플릿이라 크기가 인자마다 다르고, `ItemTables` 는 `std::vector` 를, `KiottySpecContext` 는 그것을 담은 `impl::Context` 를 가져 표준 라이브러리 구현과 Debug · Release 빌드마다 크기가 다르다 (CR-011) | 멤버는 그대로 크기 내림차순으로 둔다. 이 struct 들은 파일에 바이트 그대로 쓰지 않는다. `tools/lint.js` 는 이 셋만 3.4 의 크기 고정 검사에서 뺀다 |
| 개발수칙 3.2 (포인터로 연결된 자료구조 금지) | `app/` (CLI) | `std::map` 을 쓴다 | 1.1 · 1.6 의 CLI 예외와 같은 이유. 한 번 실행하고 끝나는 짧은 process 라 노드 할당의 캐시 손실이 문제 되지 않는다 (CR-011) | 라이브러리(`src/`)는 그대로 3.2 를 지킨다. 코드 검사는 `app/` 의 3.2 를 세지 않는다 |
| 개발수칙 1.3 (반복 생성 · 소멸되는 인스턴스는 풀 + Handle) | `ItemTables::tags` (`data/repository/item/kiotty_item_tables.h`), `RelationStore::_records` (`data/repository/relation/kiotty_relation_store.h`) | 지금 붙어 있는 태그 · 관계를 풀과 `{index, generation}` Handle 없이 (항목 index, 순번) 순으로 정렬한 `std::vector` 에 밀어 넣고 당겨 지운다 | 태그 · 관계는 홀로 가리킬 대상이 아니라 항목 쌍에 딸린 값이라 밖으로 Handle 을 내줄 일이 없다. 정렬 배열이어야 한 항목의 태그 · 관계를 이분 탐색 한 번과 연속 구간으로 읽고, Finder · Checker 가 표 전체를 index 순서로 한 번 훑어 항목별 값 · 개수를 모으며(3.3), 체크포인트 버전 표와 비교 순서를 같은 키로 맞춘다. 풀로 옮기면 슬롯이 흩어져 이 순서를 따로 다시 세워야 한다 (CR-001) | 용량은 초기화 때 `max_tags` · `max_relations` 로 한 번 잡고 크기를 바꾸지 않는다(1.1). 넣기 전에 가득 참을 검사해 `POOL_IS_FULL` 을 돌려준다. 항목을 지우면 그 항목의 태그 · 관계를 같은 쓰기 안에서 함께 지워 남은 index 가 다른 항목을 가리키지 않게 한다. 밖으로는 항목 Handle 만 나간다 |
| 개발수칙 7.2 · 7.3 (presentation 은 domain 을 거쳐 datalayer 를 쓴다) | `app/cli/src/presentation/` | CLI handler 가 라이브러리 C interface(`include/kiotty_spec.h`)를 바로 부른다 | 라이브러리의 C 함수 하나가 사용자 기능 하나라 CLI 의 domain/usecases 에 해당하고, 저장소는 라이브러리 안에 있다. CLI 에 같은 함수를 한 번 더 감싸는 usecase · repository 층을 두면 호출만 옮기는 코드가 함수 수만큼 생긴다 (CR-005) | CLI 는 C interface 말고 `src/` 내부 헤더를 include 하지 않는다. `tools/lint.js` 는 `cli/presentation` 이 `include/` 를 쓰는 것만 7.3 에서 허용한다 |
| 개발수칙 4.17 (method 는 짧은 동사) | `tools/lint_accepted.txt` 의 117 개 이름 (122 곳). 예: `range`, `point`, `items`, `relations`, `option`, `flag`, `usage` | CP-0022 코드 검사 때 있던, 동사로 시작하지 않는 이름을 그대로 둔다 | CR-007 의 예외(속성 조회 · 타입 변환 · 색인 · 커서 next)에 들지 않는 조회 · 생성 · CLI 함수 이름이다. 바꾸면 거의 모든 모듈과 설계 항목의 인터페이스 이름이 바뀌는데 동작 이득이 없다 (CR-014, 사용자 결정 2026-11-13) | 새 이름은 4.17 을 지킨다. `tools/lint.js` 는 목록에 있는 (파일, 이름) 만 세지 않으므로 새로 생긴 위반은 그대로 잡힌다 |
| 개발수칙 3.3 (순회는 index 순서로 풀 전체를 훑는다) | `Finder::pushMarked` · `Finder::relationsByModel` (`context/kiotty_finder.cpp`), `ItemDiffQuery` · `RelationDiffQuery` (`context/kiotty_item_diff_query.cpp`, `context/kiotty_relation_diff_query.cpp`) | 결과를 ID 순서로 내보내려고 ID 색인 순서로 읽고, diff 질의는 key 마다 정렬된 버전 표를 이분 탐색한다 | 커서 결과는 ID 순서여야 사람과 AI 가 읽고 비교하기 쉽다. 조건에 맞는 항목 표시는 index 순서 한 번 훑기로 하고 내보내기만 색인을 따른다. 버전 표는 정렬돼 있어 key 하나의 탐색이 O(log n) 이고, 질의는 사용자가 부를 때만 돈다 (CR-014, 사용자 결정 2026-11-13) | 풀 전체 스캔과 Checker 의 집계는 index 순서를 지킨다. 결과 수는 커서 행 상한(`max_cursor_rows`)으로 묶인다 |
| 개발수칙 4.2 (한 함수는 한 추상 수준) | `StructureEditor::insertItem` · `ContentEditor::updateItem` (`domain/usecases/editor/kiotty_editor.cpp`), `OpenedContext::initialize`, `Finder::impact`, `HistoryFinder::position`, `KiottySpec_fetchItemDiffPage` · `KiottySpec_fetchRelationDiffPage` (`src/kiotty_spec_diff.cpp`), `KiottySpec_readPosition` (`src/kiotty_spec_checkpoints.cpp`), `KiottySpec_readModel` (`src/kiotty_spec_models.cpp`) | 흐름 함수 안에서 C 레코드 필드 복사나 한두 줄의 선택 · 검증을 직접 한다 | 필드 복사와 짧은 선택을 보조 함수로 빼면 한 번만 불리는 함수가 늘어 오히려 읽기 어렵다 (CR-014, 사용자 결정 2026-11-13) | 함수는 4.1 의 한계(본문 30 줄, 중첩 2 단) 안에 있다. 새 흐름 함수는 4.2 를 지킨다 |
| 개발수칙 6.1 (작업 순서는 타입으로 강제) | `KiottySpec_open` (`include/kiotty_spec.h`), `OpenedFile::close` (`data/datasource/kiotty_opened_file.h`), `FileWriter::write` (`data/datasource/kiotty_file_writer.cpp`), `KispFileWriter::commit` (`data/datasource/kiotty_kisp_file.h`), `Lifecycle::complete` (`domain/usecases/lifecycle/kiotty_lifecycle.h`) | 열기 · 닫기 · commit · 확정의 순서 일부를 런타임 상태로 지킨다 | C interface 는 C 타입만 쓸 수 있어, 연 컨텍스트를 다른 타입으로 돌려주면 모든 함수의 인자 타입이 둘로 갈린다. 파일 닫기와 commit 은 소멸자 정리와 함께 쓰여 이동 · 닫은 뒤 상태를 런타임으로 본다. `Lifecycle::complete` 는 `ContextWriteSide::completeCheckpoint` 만 부른다 (CR-014, 사용자 결정 2026-11-13) | 열지 않은 컨텍스트와 닫힌 파일은 `PRECONDITION` 으로 거부하고, 시스템 테스트와 E2E 테스트가 이를 검사한다. 라이브러리 안의 Context · 파일 읽기 순서는 `OpenedContext` · `OpenedFile` 타입으로 강제한다 (CR-002) |
| 개발수칙 6.3 (한 흐름은 한 맥락) | `HistoryFinder::position` (`context/kiotty_history_finder.cpp`) | 현재 체크포인트, 확정 안 된 쓰기 수, 열린 변경 요청 수, 다음 단계를 한 함수에서 모은다 | 현재 위치는 한 번에 계산해 돌려주는 조회 하나이고, 나누면 같은 체크포인트 표를 여러 번 읽는다 (CR-014, 사용자 결정 2026-11-13) | 열린 변경 요청 수와 가장 이른 진입 단계는 Checker 가 계산하고, `position` 은 결과를 모으기만 한다 |
| 개발수칙 6.4 (엣지 케이스는 흐름이 삼킨다) | `BodyStore::put` (`data/repository/item/kiotty_body_store.cpp`), `ItemWriter::writeBody` (`data/repository/item/kiotty_item_writer.cpp`) | 빈 본문을 따로 분기해 저장하지 않고 해시 0 으로 둔다 | `.kisp` 형식(v2)이 빈 본문을 본문 줄 없이 해시 0 으로 나타낸다. 고치려면 파일 형식을 바꿔야 한다 (CR-014, 사용자 결정 2026-11-13) | 형식을 바꿀 때 없앤다. 빈 본문 쓰기 · 읽기는 유닛 · 시스템 테스트가 덮는다 |
