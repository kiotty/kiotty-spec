## 1. 마일스톤 ID 형식이 definition.md 와 다름

**현상**
definition.md 2.2 와 3 절의 예시는 `MS-02` (두 자리)인데, `ks item create milestone` 은 `MS-001` (세 자리)을 발급한다.
예시대로 `MS-01` 을 가리킨 스크립트가 `ks link add MS-01 covers ...` 에서 `NotFound` 로 멈췄고, 다시 실행하자 같은 마일스톤이 MS-004 ~ 006 으로 한 번 더 생겼다.

**요구**
- 정의서와 구현 중 하나로 맞춘다. 다른 항목이 모두 세 자리이므로 definition.md 의 예시를 `MS-002` 로 고치는 쪽을 권한다.
- 또는 `MS-2`, `MS-02`, `MS-002` 처럼 숫자 부분의 자릿수가 달라도 같은 항목으로 해석한다.

## 2. `--category` 가 영문 이름만 받음

**현상**
`ks item template requirement --category 품질` 은 `InvalidArg: 알 수 없는 ItemCategory 이름: '품질'` 로 실패한다. 받는 값은 `quality` 같은 영문 이름인데, 정작 템플릿·export·보고서는 "품질", "C 함수·타입" 같은 한글 라벨로 출력한다.
받는 값 목록은 소스(`names.cpp`)를 열어야 알 수 있었다.

**요구**
- `--category` 가 한글 라벨(`기능`, `C 함수·타입` 등)도 받는다.
- 이름이 틀리면 오류 메시지에 받을 수 있는 값 목록(영문 이름 + 한글 라벨)을 보여 준다. 같은 처리를 KIND, ROLE, TYPE 인자에도 적용한다.

## 3. 같은 제목의 항목을 다시 만들어도 경고가 없음

**현상**
`ks item create` 는 같은 종류·같은 제목의 항목이 이미 있어도 새 ID 로 하나 더 만든다. AI 가 스크립트를 다시 돌리면 항목이 조용히 중복된다 (1번의 MS-004 ~ 006).

**요구**
- 같은 종류·같은 제목의 항목이 현재 뷰에 있으면 stderr 에 경고하고 기존 ID 를 알려 준다.
- `--if-absent` (있으면 기존 ID 를 돌려주고 만들지 않음) 또는 `--upsert` (있으면 본문 갱신) 같은 선택지를 둬서 스크립트를 다시 실행해도 안전하게 한다.

## 4. Step 2 를 건너뛰면 "건너뜀" 으로 보임

**현상**
Step 1 직후 피드백 없이 Step 3 으로 가면 `ks where` 의 지나온 단계에 "Step 1 에서 건너뜀" 으로 표시된다. Step 2 는 피드백이 있을 때만 도는 단계라서, 피드백이 없으면 Step 1 → 3 이 정상 흐름이다.

**요구**
- Step 1 → Step 3 은 "다음 단계" 로 보인다. "건너뜀" 은 정말 단계를 빠뜨렸을 때(예: Step 4 → Step 6)만 쓴다.
- 함께 정할 것: Step 2 확정 없이 Step 3 으로 갈 때, Step 1 확정이 Step 2 확정 조건(R-4)을 대신하는지 definition.md 에 적는다.
