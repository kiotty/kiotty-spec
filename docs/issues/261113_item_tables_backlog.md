# [백로그] 항목 본문에 묶는 참조 표 (2026-11-13)

상태: 백로그. 반영 계획 없음. 변경 요청 상태 `백로그` 가 생기면(CR-015 모델 2) 변경 요청 항목으로 옮기고 이 파일은 지운다.

## 문제

변경 요청의 "전용 개발 수칙 처리 표" 처럼 행 · 열이 있는 데이터를 지금은 Markdown 본문 안에 표로 쓴다.

- 기계가 읽을 수 없다. "처리가 `미정` 인 행이 남았나" 를 확정 조건으로 검사할 수 없고, AI 가 본문 전체를 읽어야 한다.
- 행 하나만 바꿔도 본문 전체가 새 버전이 된다. 체크포인트 비교에서 어느 행이 바뀌었는지 보이지 않는다.
- 본문 한도(16 KB) 안에 표와 글이 같이 들어가야 한다.

## 생각

항목에 붙는 표를 따로 기록하고, 본문에서는 링크로 가리킨다.

- 표 정의: `ID  [열 개수]  [열 이름 1]  …  [열 이름 n]`
- 행: `ID  [1x1 칸]  [1x2 칸]  …  [1xn 칸]`, 다음 행도 같은 모양
- 본문에는 표 자리에 링크만 둔다 (예: `<?table TBL-003?>`). 읽는 쪽이 펼친다.

예 (처리 표):

```
TBL-003  6  PRULE  대체하던 수칙  변경  필드  처리  근거
TBL-003  PRULE-002  RULE-029  removed  -  미정  -
TBL-003  PRULE-005  RULE-031  modified  body  유지  공통 수칙이 같은 뜻으로 바뀜
```

## `.kisp` 에 넣는 방법 (기존 파일을 건드리지 않음)

- 새 `TABLE item_table` (표 키, 항목 키, 체크포인트, 열 이름들) 과 `TABLE item_table_row` (표 키, 행 번호, 체크포인트, 칸들) 를 파일 끝에 덧붙인다. 표가 없는 옛 파일은 그대로 열린다.
- 행마다 체크포인트 버전을 둔다 (지금 `item_version` 과 같은 방식). 체크포인트 비교에서 "TBL-003 2 행의 처리: 미정 → 유지" 가 보이고, prune 도 같은 규칙을 쓴다.
- 칸은 글만 담는다. 형식 버전 또는 모델 버전을 올린다.

## 정할 것

- 행의 정체성: 행 번호(순서) 인가, 첫 열을 키로 쓰는가. git 병합 충돌이 덜 나는 쪽은 키.
- 용량: 표당 열 · 행 수와 칸 길이의 상한 (수칙 1 장 메모리 예측 가능성).
- C API: 표 만들기 · 행 쓰기 · 행 커서(열 = 값 조건) · 지난 시점 읽기, 그리고 체크포인트 비교에 표 변화 넣기.
- `ks` 출력: 표는 TSV 그대로 (최소 출력 원칙과 맞음). 본문을 찍을 때 링크를 펼칠지.
- 크기: 지금 처리 표 하나 때문에 만들기에는 크다. 쓸 곳이 둘 이상 생길 때 진행한다.
