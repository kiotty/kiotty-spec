# kisp 텍스트 형식 (2026-11-10)

SQLite DB 를 사람이 읽고 git 이 병합하는 텍스트 파일 `.kiotty/spec.kisp` 로 바꿨다. 파일이 곧 커밋 대상이므로 jsonl 교환, git 훅, `.gitignore` 관리는 없어졌다. Tauri 플러그인보다 먼저 했다 (사용자 결정 2026-11-10).

## 1. 원칙

- **파일은 저장 형식, 질의는 메모리.** 열 때 파일을 전부 읽어 버전 표와 현재 뷰(항목 · 태그 · 관계 풀)를 만든다. 검색 · 관계 · 영향 분석은 지금처럼 풀에서 한다. 쓰기마다 파일을 통째로 다시 쓴다 (이 저장소 93 KB, 1,210 줄).
- **참조는 줄 번호가 아니라 키.** 항목은 만들 때 뽑는 8자리 16진수 key 로 서로를 가리킨다. handle 은 메모리에서만 쓴다. git 은 줄 위치가 아니라 내용과 앞뒤 문맥으로 비교하므로 줄이 밀려도 상관없다.
- **append 가 아니라 정렬.** 줄은 (표, 정체성, 체크포인트) 순이다. 다른 레코드의 변화는 파일의 다른 자리에 생겨 git 이 합치고, 같은 레코드만 충돌한다.
- **한 줄 = 레코드 한 버전.** "그 시점의 값" 은 정체성마다 그 체크포인트 이하의 마지막 줄이다.

## 2. 형식

```
#kisp 1 model 1
TABLE	meta	O/X	key	value
meta	O	project.name	kiotty-spec
TABLE	checkpoint	O/X	sequence	previous	step	state	created_at	description
checkpoint	O	7	6	4	running	1793859174	Step 4 라운드 1: 설계 44개 (디렉토리 6, 메모리 정
TABLE	item	O/X	key	id
item	O	a1b2c3d4	DSN-021
TABLE	item_version	O/X	key	checkpoint	kind	parent	title	summary	body
item_version	O	a1b2c3d4	7	design	9f0e1d2c	MilestoneService	마일스톤 포함 항목 상태	3fa9c2e1b07d4466
TABLE	tag	O/X	key	tag	checkpoint	value
tag	O	a1b2c3d4	구현 상태	7	구현 완료
TABLE	relation	O/X	from	model	relation	to	checkpoint
relation	X	a1b2c3d4	design	관련 요구사항	e5f6a7b8	7
TABLE	decision	O/X	kind	checkpoint	text
decision	O	design	7	- DSN-001 · 출처 : ...\n- DSN-002 ...
```

- 첫 줄은 형식과 모델 버전이다. 모델 버전은 코드에 박혀 있고, 다르면 열지 않는다.
- 1열은 표 이름이다. 줄마다 쓴다. git diff 조각에는 `TABLE` 머리줄이 안 보이므로 줄 하나만으로 표를 알아야 한다. `TABLE` 줄과 `#` 줄은 사람용이며 읽을 때 건너뛴다.
- 2열은 `O` (살아 있음) 나 `X` (툼스톤: 그 체크포인트에 지워짐) 다.
- 태그 · 관계 · Kind 는 번호가 아니라 이름으로 쓴다. 태그 값은 비트 이름을 쉼표로 잇는다. 번호는 읽을 때 모델 표에서 찾는다.
- 필드는 탭으로 나누고 `\t` `\n` `\r` `\\` 만 이스케이프한다. 키 · 해시 · previous 의 "없음" 은 `-` 이고, 빈 요약은 빈 필드다.
- 정렬: meta 는 key, checkpoint 는 sequence, item 은 key, item_version 은 (key, checkpoint), tag 는 (key, 태그 index, checkpoint), relation 은 (from, 관계 index, to, checkpoint), decision 은 (Kind, checkpoint).
- 본문은 `.kiotty/spec/<key>.md` 에 현재 것만 둔다. item_version 의 `body` 열은 본문의 64비트 FNV-1a 해시다.

## 3. DB 처럼 쓰기

| 동작 | 하는 일 |
| --- | --- |
| 열기 | 줄을 버전 표에 넣고 정렬한다. 같은 (표, 정체성, 체크포인트) 가 두 줄이거나 같은 ID 가 두 키에 있거나 `<<<<<<<` 줄이 있으면 줄 번호와 함께 거부한다. 없는 파일이면 빈 파일을 만든다 |
| 검색 | 바뀌지 않았다. 현재 뷰에서 한다 |
| 쓰기 시작 | 연 뒤에 파일이 밖에서 바뀌었으면 (줄 해시 비교) 다시 읽고 CONFLICT |
| 추가 | 키를 뽑고 `item` 줄과 현재 체크포인트의 `item_version` 줄을 넣는다 |
| 필드 변경 | 같은 (정체성, 현재 체크포인트) 줄이 있으면 바꾸고 없으면 넣는다. 한 체크포인트 안에서 몇 번 고쳐도 diff 는 한 줄이다. rename 은 `item` 줄 하나다 |
| 삭제 | 현재 체크포인트에 `X` 줄을 둔다. 항목을 지우면 딸린 관계도 `X`. `item` 줄은 정리 전까지 남아 그 ID 를 다시 못 쓴다 |
| 쓰기 끝 | 성공이면 `<파일>.tmp` 에 전부 쓰고 rename 으로 바꾼다. 실패면 파일에서 다시 읽어 메모리의 변경을 버린다 |
| 정리 (prune) | 기준 이하 버전을 정체성마다 하나로 접고 `X` 를 지운다. 버전이 없어진 항목의 `item` 줄과 본문 파일도 지운다 |

- 키는 `mix64(FNV-1a(ID, 시각 + 시도 횟수))` 의 32비트다. FNV 만 쓰면 끝 글자만 다른 ID 의 키가 이웃해 git 충돌이 났다.
- 다음 ID 번호는 `item` 줄 (지운 항목 포함) 에서 접두어별 가장 큰 번호 + 1 이다. `id_counter` 는 병합마다 충돌해서 없앴다.
- 버전 표 용량은 현재 풀의 4 배 (`VERSION_FACTOR`), 결정 기록 버전은 1024 개다. 넘치면 POOL_IS_FULL 과 "정리할 것".
- `readItemBodyAt` 은 그 시점의 본문 해시가 지금과 같을 때만 읽는다. 과거 본문은 git 이력에 있다.

## 4. 바뀐 공개 인터페이스

- 지움: `KiottySpec_exportJsonl`, `KiottySpec_importJsonl`. `ks export` · `ks import`.
- `KiottySpec_initProject(context, name)`: git 훅 인자를 뺐다. `ks init --hooks` 도 없다.
- `ks` 는 SQLite 파일을 열면 "첫 줄이 #kisp 1 model 1 이 아님" 으로 거부한다.

## 5. 옮기기

`tools/kisp_from_jsonl.py <jsonl 디렉토리> <.kisp>` 가 스키마 3 jsonl (item.jsonl 이 있는 형식) 을 바꾼다. 더 옛 형식은 커밋 4205e5d 의 `ks` 로 먼저 `ks import jsonl` · `ks export jsonl` 한다.

이 저장소의 결과:

- 변환한 파일을 C++ 가 읽고 바꾸지 않고 다시 쓰면 바이트가 같다.
- 바꾸기 전에 저장한 `ks` 출력 16 개 (item list, 태그 · 관계 열, 체크포인트, history, diff 요약 · Kind 별 · 필드별, 관계, impact, 본문, 결정 기록, children, model) 가 모두 바이트까지 같다.

## 6. 병합 시험

임시 git 저장소에서 두 브랜치를 만들어 합쳤다 (`temp/merge_*.sh`, 커밋하지 않음).

| 경우 | 결과 |
| --- | --- |
| 같은 진행 중 체크포인트에서 서로 다른 항목 추가 · 요약 수정 · 본문 · 태그 · 관계 | 충돌 없이 자동 병합. 양쪽 변경이 모두 보인다 |
| 양쪽이 각자 새 체크포인트를 시작 | `checkpoint 2` 줄만 충돌. 체크포인트 번호가 전역 순번이라서다 (백로그 #2, 포기함). 항목 줄은 합쳐진다 |
| 충돌 표시를 남긴 채 열기 | 줄 번호와 함께 CONFLICT |

## 7. 남은 것

- 두 브랜치가 각자 체크포인트를 시작하면 번호가 겹친다. 한쪽 번호를 손으로 고쳐야 하고, 그 번호를 쓰는 버전 줄도 함께 고쳐야 한다. 지금은 한 사람 관리 전제라 그대로 둔다.
- 두 브랜치가 같은 ID 를 발급하면 열 때 "같은 ID 를 가진 항목이 둘" 로 거부한다. `item` 줄의 ID 하나를 손으로 바꾸면 된다.
