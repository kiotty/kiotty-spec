이 페이지는 node tools/ui_doc.js 가 ks 의 외부 인터페이스 항목(인터페이스 종류 = GUI 뷰) 8 개에서 만든다. 고칠 때는 ks 로 항목을 고치고 다시 만든다. 화면 그림은 항목 본문의 wireframe 블록이다.

UI-168

브라우저 뷰어

GitHub Pages 정적 뷰어. 링크나 로컬 파일로 .kisp 를 열어 개요 · 진행 · 항목 · 변경 요청을 보인다. 보기 전용

관련 요구사항 REQ-052 설치 없이 브라우저에서 사양 기록을 본다 REQ-059 뷰어 실행 환경

목적

설치 없이 브라우저에서 사양 파일(.kisp)을 보는 정적 웹 뷰어. 보기 전용이며 사양 파일 해석은 wasm32 로 빌드한 라이브러리가 한다.

공통 구성

  • 머리 줄: 뷰어 이름, 연 원천(저장소 @ 버전 또는 로컬 파일 이름), "다른 파일 열기" (UI-170 으로)
  • 탭: 개요 · 진행 · 항목 · 변경 요청. 항목 상세(UI-174) 는 탭이 아니라 링크로 연다
  • 화면 상태는 주소의 # 뒤에 둔다 (UI-169). 브라우저 뒤로 가기 · 앞으로 가기 · 새로 고침이 그대로 동작한다
  • 쓰기 단추 · 입력이 없다. 사양 파일을 바꾸는 방법은 화면에 없다

사전조건

  • 지원 브라우저: Windows · macOS 의 크롬 · 엣지 · 사파리 최신 두 주 버전 (REQ-059)
  • JavaScript 와 WebAssembly 가 켜져 있다

사후조건

  • 뷰어는 저장소 · 로컬 파일에 아무것도 쓰지 않는다
  • 사양 파일은 브라우저 메모리에서만 연다. 탭을 닫으면 사라진다

오류 표시

  • 불러오는 중: 머리 줄 아래 진행 표시
  • 브라우저가 WebAssembly 를 지원하지 않음: "이 브라우저에서는 열 수 없습니다" 와 지원 브라우저 목록
  • 열기 실패: UI-170 열기 화면에 이유를 보인다
UI-169

뷰어 링크

상위 UI-168

?repo=OWNER/NAME&ref=REF&path=PATH 로 원천을, # 뒤로 화면을 정한다

관련 요구사항 REQ-053 공개 저장소의 사양 파일을 링크로 연다 REQ-057 항목 하나의 추적 관계를 따라간다

시그니처

https://<뷰어 주소>/?repo=OWNER/NAME[&ref=REF][&path=PATH][#/<화면>]

#/overview                          개요 (UI-171)
#/progress                          진행 (UI-172, 기본)
#/items/<KIND>[?tag=이름:값&q=글자]  항목 표 (UI-173)
#/item/<ID>                         항목 상세 (UI-174)
#/changes                           변경 요청 (UI-175)

매개변수

이름필수기본값뜻
repo예 (없으면 UI-170)—공개 GitHub 저장소 OWNER/NAME
ref아니오저장소 기본 브랜치태그 · 브랜치 · commit
path아니오.kiotty/spec.kisp저장소 안 사양 파일 위치
KIND——ks 의 Kind 이름 (requirement, design 등)
tag아니오—태그 거르기. 여러 번 쓸 수 있다
q아니오—제목 · 요약 글자 찾기

모든 값은 URL 인코딩한다 (한글 태그 이름 포함).

사전조건

  • 저장소가 공개이고, 그 ref 에 path 파일이 있다

사후조건

  • https://raw.githubusercontent.com/OWNER/NAME/REF/PATH 를 받아 연다
  • 같은 링크는 누가 열어도 같은 내용을 보인다 (ref 가 태그 · commit 일 때)
  • # 뒤만 바뀌면 파일을 다시 받지 않는다

오류 표시

열 수 없으면 UI-170 열기 화면에 아래 문구와 입력한 값을 채워 보인다.

  • 저장소를 찾지 못함: "저장소 OWNER/NAME 을 찾지 못했습니다 (없거나 비공개)"
  • 버전을 찾지 못함: "버전 REF 를 찾지 못했습니다"
  • 파일을 찾지 못함: "REF 에 PATH 가 없습니다"
  • 형식이 다름: "사양 파일 형식이 아닙니다 (N 번째 줄)" 또는 "이 뷰어가 모르는 모델 버전입니다"
  • 너무 큼: "기록이 뷰어 용량보다 큽니다"
  • 네트워크 실패: "파일을 받지 못했습니다" 와 다시 시도
  • 없는 KIND: 항목 화면에 "없는 종류: KIND". 없는 ID: UI-174 의 없는 항목 표시
  • 비공개 저장소 · 찾지 못함 문구에는 로컬 파일 열기 안내를 붙인다 (REQ-054)
UI-170

열기 화면

상위 UI-168

관련 요구사항 REQ-053 공개 저장소의 사양 파일을 링크로 연다 REQ-054 내 PC 의 사양 파일을 끌어 놓아 연다

목적

링크에 저장소가 없거나 열기에 실패했을 때, 또는 "다른 파일 열기" 를 눌렀을 때 원천을 고른다.

구성

  • 공개 저장소 입력: 저장소(OWNER/NAME), 버전, 파일 위치. 앞서 실패한 링크의 값을 채워 둔다
  • 열기: 입력값으로 UI-169 링크를 만들어 그 주소로 간다 (링크를 복사해 보낼 수 있다)
  • 끌어 놓기 상자 · 파일 고르기: 로컬 .kisp 를 연다
  • 오류 알림: UI-169 의 문구

사전조건

  • 없음

사후조건

  • 로컬 파일은 브라우저 안에서만 읽고 어디에도 보내지 않는다. 주소에 repo 를 넣지 않는다 (새로 고침하면 열기 화면으로 돌아온다)
  • 로컬 파일을 열면 머리 줄에 파일 이름을 보이고 진행 화면(UI-172) 으로 간다
  • 파일이 열린 뒤에도 뷰어 어디에든 끌어 놓으면 새 파일을 연다

오류 표시

  • 저장소 입력이 OWNER/NAME 꼴이 아님: 열기 단추 아래 "OWNER/NAME 꼴로 입력하세요", 이동하지 않는다
  • 로컬 파일 형식이 다름: "사양 파일 형식이 아닙니다 (N 번째 줄)". 앞서 연 파일이 있으면 그대로 둔다
  • 여러 파일을 끌어 놓음: 첫 파일만 열고 "파일 하나만 엽니다" 를 알린다

구성

  • 상태 묶음 순서: 열림 · 반영 중, 백로그, 완료, 거부. 묶음마다 개수. 완료 · 거부는 접혀서 시작한다
  • 줄: ID, 제목, 요약(마우스를 올리면), 출처, 진입 단계, 영향 항목 수 (변경 요청에서 나가는 관계 수)
  • 줄을 누르면 UI-174 항목 상세로 간다. 거기서 본문과 영향 항목을 관계 이름별로 본다
  • 묶음 안은 ID 내림차순 (새 변경 요청이 위)

사전조건

  • 사양 파일이 열려 있다

사후조건

  • 묶음의 변경 요청은 같은 파일에서 ks item list --kind change_request --tag 상태=값 과 같다

오류 표시

  • 변경 요청이 없음: "변경 요청이 없습니다"
  • 상태 태그가 없는 변경 요청: "상태 없음" 묶음을 맨 끝에 둔다
